# Альфа-Курс Navigator · Frontend

Самостоятельный React + TypeScript + Vite интерфейс. Backend, ранжирование и исходный каталог не изменены.

## Запуск

Требуется Node.js 22.12+ (проверено на 22.23.2).

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Backend не нужен. Деморежим включён по умолчанию.

```sh
npm run build
npm run preview
```

`dist/` — готовая статическая сборка. Переменные `VITE_*` встраиваются во время сборки и не должны содержать секретов.

## Что работает

- Ввод задачи до 300 символов, интерактивные примеры, валидация пустого ввода.
- Два необязательных шага персонализации: стадия / сфера, опыт / формат. Можно пропустить или сбросить.
- Рекомендации: тип, доступ, уровень, описание, раскрываемые причины. Длительность отображается только при наличии.
- Фильтр по реально представленным форматам, переключение карточек и маршрута.
- Отметки прохождения, прогресс, история последнего запроса в localStorage этого браузера. Данные не синхронизируются с аккаунтом.
- Три явно выбираемых синтетических сценария: кофейня, налоги, интернет-магазин.
- Состояния загрузки, ошибки, пустого каталога, неточных совпадений, неполного профиля и отсутствующей истории.
- Клавиатурные состояния, skip link, нативный modal dialog с Escape / focus trap, reduced motion.

## Граница демонстрации

В панели «Сценарии демо» выбираются подготовленный профиль и тестовое состояние. Это **фиксированные синтетические подборки**, а не интерпретация свободного текста и не ML-рекомендации. Произвольный запрос не запускает скрытый классификатор: остаётся выбранный демонстрационный сценарий. Тестовые карточки открывают пояснение, а не выдуманную внешнюю ссылку. Закрытого учебного содержания нет.

Официальные бренд-ассеты не использованы: знак-стрелка и маршрутная SVG-иллюстрация созданы для этого концепта. Manrope включён локально с лицензией OFL; внешних запросов к шрифтовым сервисам нет. Компоненты написаны на React / CSS с Lucide и Motion; тяжёлый UI-kit и Tailwind не добавлены без необходимости.

## Подключение существующего FastAPI

Создайте `frontend/.env.local`:

```dotenv
VITE_DATA_SOURCE=api
VITE_API_BASE_URL=http://localhost:8000
```

Запустите Backend согласно корневому README, указав разрешённый origin фронтенда:

```sh
CORS_ORIGINS=http://127.0.0.1:5173 .venv/bin/python -m uvicorn app.main:app --port 8000
```

Перезапустите Vite после изменения `.env.local`. Для production разрешите точный origin; не храните ключи в `VITE_*`.

Клиент использует существующие endpoints:

- `GET /health`: источник `synthetic` маркируется как тестовый; при неизвестном источнике внешние ссылки блокируются.
- `GET /api/v1/onboarding`: варианты берутся из каталога, не из предположений UI.
- `POST /api/v1/recommendations`: передаются `task`, опциональные поля профиля и до 100 событий `history`.

Ответ `Result` соответствует `app/models.py`. Порядок рекомендаций сохраняется, оценки и формулы ранжирования фронтенд не вычисляет. В API-режиме локальный синтетический сценарий и состояния ошибок не применяются.

Для настоящих материалов UI открывает диалог с пользой и безопасной HTTP(S)-ссылкой, только если `/health` подтвердил `catalog: local`. Синтетические URL даже из Backend не открываются.

### Маршрут и будущие расширения

Текущий Backend отдаёт `recommendations[].next_step`, но не отдельный маршрут, длительности или краткую интерпретацию задачи. Поэтому:

- В API-режиме по умолчанию отображается **полученная последовательность рекомендаций**, а не якобы ML-маршрут.
- Тип `NavigatorResponse` допускает будущие `route` и `task_summary`. `route.steps[].material_id` ссылается только на материалы ответа; неизвестные ID не отображаются.
- `Material.duration_minutes` опционален. Без него время не показывается.
- Пока нет `task_summary`, UI цитирует запрос пользователя, не выдавая его за результат анализа.

Команде Backend остаётся согласовать эти расширения, подключить реальный каталог, добавить при необходимости серверную историю / авторизацию. Клиентская типизация не заменяет проверку контракта API на сервере.

## Структура

```text
src/
  App.tsx                  пользовательский сценарий и навигация
  pages/Personalization    двухшаговая персонализация
  components/              MaterialCard, RouteArt
  tokens.css               шрифт и базовые токены
  styles.css               адаптивная дизайн-система
  types/                   контракт API и опциональный маршрут
  data/demo.ts             только синтетические демонстрационные данные
  api/client.ts            единая граница demo / API, HTTP timeout 15 секунд
  state/storage.ts         защищённый доступ к локальной истории
```

## Проверки

```sh
npx playwright install chromium
npm test
npm run build
```

Playwright: полный сценарий на 375 / 768 / 1440 px, отсутствие горизонтального переполнения и runtime-ошибок, модальный диалог / Escape, фильтр, маршрут / прогресс / reload, тестовые профили, ошибки / пустые состояния, длинный запрос, сброс параметров. Axe: автоматическая WCAG 2.1 AA проверка главной, первого шага персонализации и рекомендаций. Автоматический аудит не заменяет ручной аудит доступности.

Скриншоты генерируются в `screenshots/`.

Реальный API smoke-test (нужна `.venv` в корне с `requirements-dev.txt`; использует порты 4180 и 4181):

```sh
node tests/api-smoke.mjs
```

Он запускает текущий FastAPI, получает настоящие onboarding / recommendations, проверяет отрисовку и блокирование синтетических ссылок. Backend-тесты запускаются из корня: `.venv/bin/python -m unittest discover -s tests -v`.

Проверено в Chromium. Firefox, Safari, реальные мобильные устройства и скринридеры отдельно не проверялись. Production-деплой в эту задачу не входил.
